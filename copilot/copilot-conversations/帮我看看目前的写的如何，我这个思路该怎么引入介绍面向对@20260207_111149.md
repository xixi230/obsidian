### 从装饰器到类：`@register` 装饰的不是函数，而是类

> 我们刚才看到 `@filter.command` 装饰的是一个**函数**。但你有没有注意到，`@register` 装饰的是一个**类**？
>
> ```python
> @register("helloworld", "YourName", "一个简单的 Hello World 插件", "1.0.0")
> class MyPlugin(Star):
>     ...
> ```
>
> 这说明在 Python 里，**类也是对象**。既然函数可以被传来传去、被装饰器"劫持"，类当然也可以。

这就自然引出了 OOP 的核心问题：**类到底是什么？**

### 建议的 OOP 章节结构

```markdown
### 3. 面向对象编程 (OOP)

#### 从函数到类：为什么需要"打包"？

我们已经知道函数是对象。但当你的插件越来越复杂，你会发现：
- 你需要保存一些**状态**（比如用户的配置、连接的数据库）
- 你需要把相关的**函数**组织在一起
- 你需要让 AstrBot 框架能够**统一管理**你的插件生命周期

这时候，单独的函数就不够用了。你需要一个"容器"来打包**数据 + 行为**。这个容器就是**类 (Class)**。

#### 类的本质：一个带有方法的命名空间

还记得我们说模块是"独立的抽屉"吗？类也是一个抽屉，但它更强大：
- 模块的抽屉是**静态的**，程序启动时就固定了
- 类的抽屉是**动态的**，你可以用它创建无数个"实例"，每个实例有自己的数据

```python
class MyPlugin(Star):
    def __init__(self, context: Context):
        self.context = context  # 每个实例都有自己的 context
```

#### `class MyPlugin(Star)` 在说什么？

这一行代码包含了 OOP 的三个核心概念：

1. **类定义** (`class MyPlugin`)：创建一个新的"蓝图"
2. **继承** (`(Star)`)：这个蓝图基于 `Star` 这个"父蓝图"
3. **多态**：AstrBot 不关心你的类叫什么名字，它只关心你是不是 `Star` 的子类

#### 继承：站在巨人的肩膀上

```python
class MyPlugin(Star):
    def __init__(self, context: Context):
        super().__init__(context)  # 调用父类的初始化方法
```

`Star` 是 AstrBot 定义的"插件基类"。它已经实现了：
- 与框架通信的底层逻辑
- 生命周期管理（初始化、销毁）
- 事件分发机制

你只需要**继承**它，然后**重写**你关心的方法（如 `initialize`、`terminate`），就能拥有这些能力。

这就像你买了一辆车（`Star`），你不需要知道发动机怎么造的，你只需要学会踩油门（重写方法）。

#### `self` 是什么？

```python
async def helloworld(self, event: AstrMessageEvent):
    user_name = event.get_sender_name()
```

在 C/C++ 里，你可能见过 `this` 指针。Python 的 `self` 就是同样的东西，但有个关键区别：
- C++ 的 `this` 是**隐式的**，编译器自动传递
- Python 的 `self` 是**显式的**，你必须手动写出来

为什么？因为 Python 信奉"显式优于隐式"（Explicit is better than implicit）。

`self` 就是"当前这个实例"。当用户 A 发送 `/helloworld`，AstrBot 会找到**属于用户 A 的那个插件实例**，然后调用它的 `helloworld` 方法。

#### 类也是对象：`@register` 的秘密

```python
@register("helloworld", "YourName", "一个简单的 Hello World 插件", "1.0.0")
class MyPlugin(Star):
    ...
```

这等价于：
```python
class MyPlugin(Star):
    ...

MyPlugin = register("helloworld", "YourName", "...", "1.0.0")(MyPlugin)
```

`register` 装饰器做了什么？它把你的类**注册**到 AstrBot 的插件管理器里。当 AstrBot 启动时，它会：
1. 扫描所有被 `@register` 标记的类
2. 读取元信息（名称、作者、描述、版本）
3. 在合适的时机**实例化**你的类（调用 `__init__`）
4. 调用 `initialize()` 完成初始化

这就是框架的魔法：**你只需要声明"我是一个插件"，框架会自动管理你的生命周期**。
