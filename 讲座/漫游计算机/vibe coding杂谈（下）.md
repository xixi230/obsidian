一切都在竞争和内卷，但是实际上，目前的大模型依旧是基于**Transformer**，他虽然极为强大，**但是本质上还是一个概率预测机**
，而不是逻辑推理机。

### 引伸
概率推测机和逻辑推理机的主要区别在于处理信息的方式：
逻辑推理机基于确定性规则和严格的真理，
而概率推测机则利用概率论处理不确定性和可能性。

- **逻辑推理机**：这类系统使用形式逻辑规则（如演绎推理、归纳推理或溯因推理）来得出结论。它们的操作基于确定性的“如果X，那么Y”规则。推理过程是一个结构化的过程，涉及匹配、选择和执行规则，直到得出确定的结论。知识通常以事实和规则的形式存储在知识库中。
- **概率推测机**：这类系统使用概率模型（如贝叶斯网络或马尔可夫逻辑网）来处理不确定性和不完整信息。它们不是得出非黑即白的结论，而是计算不同结果的可能性。推断基于贝叶斯定理等统计方法，根据新数据更新其内部概率估计，从而提高预测的准确性。

目前的 **Transformer 框架大模型（如 GPT、Claude、DeepSeek、Llama 等）本质上都是“概率预测机器”**

相比传统的神经网络比如卷积、循环，Transformer架构完全基于 Self-Attention来处理序列数据。
Transformer 架构最早是在 **2017年** 由 Google 团队发表的论文中提出的[Attention Is All You Need](https://arxiv.org/abs/1706.03762)

论文：

这是论文中最经典的 **Transformer 整体架构图**。它由左侧的 **编码器 (Encoder)** 和右侧的 **解码器 (Decoder)** 两部分组成：
![[Pasted image 20260202105603.png]]
使用堆叠的自我注意力和逐点全连接层作为编码器和解码器

该图分为三个主要部分
**输入与嵌入层 (Input/Output Embedding & Positional Encoding)**
1. 首先，输入的文本（例如：句子中的每个单词）被转换成数值向量
2. 由于 Transformer 没有像 RNN 那样的序列处理顺序，它需要额外添加`Positional Encoding`（位置编码）来告知模型每个词的相对或绝对位置信息


**左侧：编码器 (Encoder) 部分 (N× 层)**
1. 编码器由堆叠的 N=6 个相同层组成
2. 每层有两个子层：**多头自注意力机制 (`Multi-Head Attention`)** 和一个简单的前馈网络 (`Feed Forward`)

**右侧：解码器 (Decoder) 部分 (N× 层)**
1. 解码器也由堆叠的 N=6 个相同层组成，但每层有三个子层
2. 增加了一个**掩码多头自注意力机制 (`Masked Multi-Head Attention`)**，这里的“掩码”确保在生成当前词时，模型只能看到已经生成的词，而不能“偷看”未来的词，保证了生成的顺序性
3. 另一个**多头注意力机制**（交叉注意力）用于从编码器的输出中提取相关信息
4. **核心功能：** 解码器负责根据编码器的输出和已经生成的部分序列，逐步生成目标序列（例如：翻译后的句子）



![[Pasted image 20260202110744.png]]


这个框架图展现的推理流程是前向传播，他不包含**反向传播（Backpropagation**和**梯度下降（Gradient Descent**等训练机制，因此再一次证实我们所说的目前大模型的知识库是静态的。

目前大模型的记忆功能实际上是一种**假象**
它并不是像人类大脑那样主动回忆，而是通过将之前的对话内容作为上下文的一部分，
每次都会重新“阅读”一次来生成回复的。
模型的参数本身在对话过程中是不会动态改变的，所以它没有真正的动态记忆

## VIBECODING（氛围编程）
利用“记忆”进行对话式开发
它不再是传统的逐行编写代码，而是开发者（甚至是非开发者）通过**自然语言提示**，与大型语言模型（LLM）像聊天一样协作，让 AI 生成功能代码

- **工作流程：** 开发者描述需求，AI 生成代码；开发者测试结果，然后通过继续对话的方式，要求 AI 进行改进或修改。

![[Pasted image 20260202111825.png]]
这种方式使得开发过程非常快速和灵活，就像与一个真正理解项目背景的 AI 伙伴进行**结对编程 (Pair Programming)** 一样，可以快速从概念原型迭代到可工作的应用。


随着项目变大，代码库会超出单个上下文窗口的限制。模型会“忘记”早期部分的细节，导致代码质量下降或出现不一致

### 1. Anthropic (Claude)
**项目级记忆 (`CLAUDE.md`)：** Anthropic 引入了一种独特的文件管理方式。开发者可以在代码库中创建特殊的 `CLAUDE.md` 文件。Claude 在工作时会自动扫描并加载这些文件到其上下文中，从而获得项目指南、代码风格或核心功能等信息。
**RAG 自动激活：** 当项目知识接近模型的上下文窗口限制（Claude 的窗口大小约为 200K token）时，Claude 会自动切换到 RAG 模式。它不再加载所有内容，而是智能检索最相关的信息，以保持响应质量和效率
**用户控制：** 用户可以查看、编辑和管理记忆摘要，甚至使用“隐身模式”进行不保存记忆的对话，确保隐私和上下文的专注

### 2.Google (Gemini)
 **巨大的上下文窗口：** Gemini 1.5 Pro 拥有高达 200 万 token 的上下文窗口，这相当于可以一次性处理大约 5000 页文本或 30,000 行代码。这种“无限上下文”本身极大地减少了对复杂外部检索系统的需求。
 **缓存优化：** 对于大型文件的处理，Google 使用了上下文缓存（Context Caching）技术。这使得开发者可以上传整个代码库或大量文档，系统只需支付一次存储费用，后续检索和处理速度非常快。
**与外部工具集成：** 尽管自身窗口巨大，Gemini 也可以通过外部开源工具（如 Mem0）集成基于向量数据库的长期记忆系统，实现跨不同对话的持久化记忆

开发使用的两种不同类型的AI开发：

**AI IDE:CURSOR**
**AI CLI:Claude Code**

AI CLI 的设计哲学：任务委派与自动化
将AI放在了shell里面工具的核心目标是让 AI 成为一个**自主代理 (Autonomous Agent)**，你可以给它一个高级目标，然后让它自己去完成一系列步骤，而不需要你的持续干预。
目前非常多的类型，比如cc，kiro cli，copilot cli，gemini cli等


AI IDE:IDE 侧边栏的设计哲学：协作与控制
更侧重于**增强式编程 (Augmented Programming）**
**实时上下文与控制：** 它们让你始终处于“驾驶座”上。你掌控着文件树、编辑器和 Git 暂存区。AI 只是提供建议、补全或在你明确要求时进行重构。
**保持心流：** 辅助工具集成在 IDE 中，旨在无缝融入你现有的工作流程，最大限度地减少上下文切换
例如 CURSOR,kiro，Antigravity，vscode github copilot ，windsurf，trae等
