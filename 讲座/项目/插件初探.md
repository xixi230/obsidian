不同编程语言的“导入（Import）”机制，表面上是代码**复用**的手段，底层其实折射了该语言对**工程化、命名空间管理以及运行效率**的不同理解

#### C++
C++ 传统的 `#include` 并不是真正的“导入”，而是**预处理器指令**
**语法特征**：`#include <iostream>`
**机制**：预处理器会直接把头文件的**全部**内容“复制、粘贴”到当前位置

**反映特性**：

- **零开销抽象**：编译器不增加额外负担，但会导致编译时间极长（重复包含同一个头文件）。
    
- **脆弱的封装**：需要依赖 `header guards`（`#ifndef`）来防止重复定义

![[Pasted image 20260203102518.png]]

你一定写过 `#include <stdio.h>`。 
这时候，编译器其实还没开始工作。真正工作的是**预处理器 (Preprocessor)**
想象你在写一篇论文（你的 `.c` 或 `.cpp` 文件），你需要引用一段别人的名言（头文件 `.h`）
**C/C++ 的做法（`#include`）**： 预处理器是个勤恳但不太聪明的抄写员。当它看到 `#include <stdio.h>` 时，它会**把 `stdio.h` 文件里几千行的代码，一行不差地复制，直接覆盖掉 `#include` 这一行**


**“零开销抽象”的代价**： C++ 为了让你在**运行程序**时非常快（零开销），它选择在**编译阶段**把所有东西都展开、复制、优化好。它把痛苦留给了编译过程，把快乐留给了运行过程


```cpp
#include "astrbot/api/event.h"
#include "astrbot/api/star.h"
// 通常需要 using namespace std; 或使用 std::
```

#### python
Python 的 `import` 是**运行时执行**的。当你导入一个模块时，Python 解释器会真的去执行那个文件,而不是像C/C++一样全部复制


> **Python 特性：**
- 使用 `import` 或 `from...import` 语句导入模块
- 支持模块化编程，避免命名冲突
- 动态导入，运行时解析

```python
from astrbot.api.event import filter, AstrMessageEvent, MessageEventResult

from astrbot.api.star import Context, Star, register

from astrbot.api import logger
```



两种导入方式：
1. **`import` 语句**

```python
import module

import module1, module2

import module as alias

import module1 as alias1, module2 as alias2

```

我们把`module`称为**命名空间**
所谓命名空间是一个从**名称到对象**的映射

访问方式：必须通过 `module.name`（点号操作符）来访问其中的内容
这最安全，因为模块名起到了前缀的作用，保护了你当前的命名空间不被“污染

**模块是“独立的抽屉”**
每个 `.py` 文件就是一个模块，它拥有自己独立的**全局命名空间**



2. **`from module import name`语句

直接将抽屉里的东西拿出来，放在当前的桌子上，因此可以直接使用**name**即可，但是如果当前环境已经有同名变量就会发生覆盖。

从 `astrbot.api.event` 这个“大仓库”里，只挑出这三个具体的“零件”放到你当前的桌面上

你现在可以直接写 `filter` 或 `AstrMessageEvent`。它们被直接绑定到了你当前模块的**全局作用域**中



从最开始的导入，我们就可以深刻的感受到python的底层理念：模块即对象


在 Python 看来，`astrbot.api.event` 本身就是一个 **[Module 对象](https://docs.python.org/3/reference/import.html)**


**物理上**：它是磁盘上的一个 `.py` 文件或一个包含 `__init__.py` 的文件夹
**逻辑上**：它是一个容器（即命名空间），用一个**字典（**`__dict__`）维护着所有的变量名和它们的内存地址


**导入的本质**：导入不是“复制代码”，而是“**建立引用**”。当你 `import` 时，Python 只是在你的命名空间里增加了一个指针，指向了目标模块里的对象

>当你多次 `import astrbot` 时，Python **并不会**执行该文件多次
>
>Python 在第一次导入时，会执行代码并把生成的模块对象存入 `sys.modules` 这个全局字典里。后续的 `import` 只是在你的局部空间加了个“快捷方式”指向这个现成的对象

### Go

它不会盲目的复制，而是读取编译后的二进制导出文件`.a` 文件

**核心特性：强制导出规则**。Go 规定：首字母大写的变量/函数才能被外部导入（Public），小写的只能在包内使用（Private）。

**命名空间**：Go 强制要求通过包名访问（如 `fmt.Println`），**不允许**类似 Python 的 `from fmt import Println` 这种“污染桌面”的操作。这体现了 Go 极端的**工程严谨性**

Go 抛弃了预处理器（Preprocessor）。Go 的编译器直接处理语法树

但是我们可以直接查看GO编译后的导出数据

`go tool compile -S yourfile.go`查看汇编

### 装饰器和元编程

`@register`, `@filter`
代码中的 `@register` 和 `@filter.command` 看起来很像 Java 的注解（Annotation），但它们是一回事吗？

```python
@register("helloworld", "YourName", "一个简单的 Hello World 插件", "1.0.0")
class MyPlugin(Star):
    # ...

@filter.command("helloworld")
async def helloworld(self, event: AstrMessageEvent):
    # ...
```

Astrbot究竟是如何直到你写了一个叫`helloworld`的函数的？它怎么直到有人开发/helloworld的时候要找到这个函数？

答案就在`@`里

语法糖，顾名思义，你在喝药的时候，会十分痛苦，但是把药裹上一层糖的外衣，你喝药会更加顺畅
它指的是编程语言中添加的某种语法，这种语法**对语言的功能没有影响，但更方便程序员使用**
通俗地说：**只有写法变了，底层逻辑完全没变。**

在装饰器这里，`@` 就是那个糖衣
在 Python 里，这不叫“注解”，叫**装饰器 (Decorator)**。它不是给编译器看的标签，它是一个**捕兽夹**

在C里，“函数即变量”，函数指针是指向代码段的**内存地址**，这是静态的，冰冷的，无法改变的
你不能给函数添加属性，也不能像传变量一样随意把它传来传去

而在pyhon里，“**一切都是对象**”
函数是一个对象（Object），就像整数 `1` 或字符串 `"abc"` 一样。你可以把它赋值给变量，也可以把它传给另一个函数。
它存储在堆内存（Heap）中，有自己的属性（比如 `__name__`，`__doc__`）


正因为函数是对象，所以：

1. 它可以被赋值给变量。
    
2. 它可以作为参数传给另一个函数。
    
3. **它可以作为另一个函数的返回值。**

前置知识：官方文档
```python
def decorator(func):
    def wrapper():
        print("Something is happening before the function is called.")
        func()
        print("Something is happening after the function is called.")
    return wrapper

def say_whee():
    print("Whee!")

say_whee = decorator(say_whee)
```

在`decorator`本质是一个高阶函数，我们的`decorator`内又嵌入了一个`wrapper`函数。实际上我们要记住`decorator`就是一个可以不修改有原来函数情况下拓展函数功能的组合包就行了。

`def decorator(func)`:我们称为外层函数，用来接收我们想要拓展功能的原函数`func`
`def wrapper()`则是内层函数，我们实际上用wrapper来进行拓展函数，你可以在`func`前或者后面拓展其功能。
在例子中我们在`func`的前后都拓展了`print`
在最后`wrapper`会将组合好后的`wrapper`返回

在后面我们定义了一个原函数`say_Whee`，他的副作用是打印出`Whee!`
重点在于`say_whee = decorator(say_whee)`
实际上在解释器执行这句命令的时候，`say_whee`不再是被绑定在单纯的打印了，而是被作为原函数绑定在装饰器，作为`wrapper`被返回

所以之后我们一旦执行代码`say_Whee()`实际是在调用内容拓展后的`wrapper`


### 语法糖
实际上目前的思想是优雅的，我们实现了不破坏而是复用。
但是目前的语法很不优雅，我们甚至重复写了三次 `say_whee`的名称

因此python允许我们在编写装饰器的时候使用更简洁的语法来减少重复的字段

@语法也称之为 [pie syntax](https://www.python.org/dev/peps/pep-0318/#background)

```python
def decorator(func):
    def wrapper():
        print("Something is happening before the function is called.")
        func()
        print("Something is happening after the function is called.")
    return wrapper

@decorator
def say_whee():
    print("Whee!")
```
以上代码和
所以， `@decorator` 只是 `say_whee = decorator(say_whee)` 的简写。这是你将装饰器应用于函数的方式。

### 稍微复杂的装饰器（参数）
还是我们定义一个装饰器
```python
from datetime import datetime
def night(func):
    def wrapper():
        if 0 <= datetime.now().hour < 5:
            func()
        else:
            pass                  
    return wrapper

@night
def say(name):
    print(f"Good night! {name}!")
```

当我们想要调用的时候
```python
from my_time import say

say(name="Shiro")
```
运行python解释器报错：
```python
(.venv) PS E:\astrbot\shiro\data\plugins> python .\test_time.py
Traceback (most recent call last):
  File "E:\astrbot\shiro\data\plugins\test_time.py", line 3, in <module>
    say(name="Shiro")
    ~~~^^^^^^^^^^^^^^
TypeError: night.<locals>.wrapper() got an unexpected keyword argument 'name'
```

当我们检查的时候会发现我们的wrapper没有接收参数的入口，就像是一个没有信封口的信封，我们硬将信塞进去，当然会抛出`got an unexpected keyword argument 'name'`


在 Python 中，装饰器如果要兼容带参数的函数，标准做法是使用 **`*args`** 和 **`**kwargs`**
```python
from datetime import datetime

def night(func):
    # 使用 *args 和 **kwargs 接收所有位置参数和关键字参数
    def wrapper(*args, **kwargs):
        if 7 <= datetime.now().hour < 24: # 为了方便测试，改了下时间范围
            # 将收到的参数原样传给原函数
            return func(*args, **kwargs)
        else:
            print("It's not night time yet!")
    return wrapper

@night
def say(name):
    print(f"Good night! {name}!")

# 现在这样调用就不会报错了
say(name="Shiro")

```

**`*args` (Arguments)**：接收所有的**位置参数**（如 `say("Shiro")`），并将它们打包成一个元组。
**`**kwargs` (Keyword Arguments)**：接收所有的**关键字参数**（如 `say(name="Shiro")`），并将它们打包成一个字典
**`func(*args, **kwargs)`**：这一步叫**参数解包**。它把包装纸收到的所有礼物原样拆出来，递给真正的 `say` 函数

当python解释器读到这段代码时：
```python
@filter.command("helloworld")
async def helloworld(self, event):
    ...
```
解释器实际上在后台悄悄执行了一次“偷梁换柱”。上面的代码完全**等价于**：

```python
# 1. 先老老实实定义这个函数
async def helloworld(self, event):
    ...

# 2. 立即执行装饰器函数，把 helloworld 传进去
# 这里的 behavior = filter.command("helloworld") 返回了一个真正的装饰器函数
# 然后 helloworld 被传给这个装饰器，结果又重新赋值给了 helloworld
helloworld = filter.command("helloworld")(helloworld)
```

这就是装饰器的真面目：**它是 module 加载时的“劫持”行为**


>装饰器是一个函数，接受一个函数或方法作为其唯一的参数，并返回一个新函数或方法，其中整合了修饰后的函数或方法，并附带了一些额外的功能．简而言之，可以在不修改函数代码的情况下，增加函数的功能．--oi.wiki
